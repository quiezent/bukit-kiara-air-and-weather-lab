# Server/device contract update — 9 October 2026

I updated the forecasting server's compact device projection to **v24.0.3-public.1**, corresponding to local v24.0.3. Coach remains **1.37.0** and RLCD remains **schema 1**, with additive fields. The [installation guide](SERVER_RELEASE_2026_10_08.md), scoped [Apache-2.0 license](../app/LICENSE.md), private-data boundary and Afternoon provisioning limitation still apply.

The device response now includes `current.display_text`, matching the web's `Latest sensor reading` or recent `Observed: …` label. `forecast.near90.arrival_change` adds `display_text`, `outcome`, `outcome_probability`, `within20`, `issued_epoch` and `fresh_reference_epoch`. The headline describes the largest of the native fall ≥20, rise ≥20 and within-20 arrival probabilities. Clients can append its percentage, such as the synthetic example `No change on arrival 92.1%`. Exact ties say `Arrival outcome uncertain` and have no winning probability. These are arrival endpoint outcomes; the separate first-crossing fields retain their original meaning.

The projection rejects incoherent probabilities, mismatched or fractional source clocks, invalid reference values and fresh-reference samples more than 240 seconds before issue. Numeric-point availability is separate: the categorical outcome can remain valid while the point is unavailable and its reference is retained. Existing parent issue, delivery and sensor stale/unavailable guards remain. None of these fields selects, scales or replaces a numerical model forecast. The [API guide](COACH_API.md#rlcd-web-text-and-observed-history-v2403-october-9-2026) describes the fields and display clocks.

I found that the server's old **8,192-byte** limit aggressively thinned six-hour history to four points although the firmware accepts **16,384 bytes** and **128 points**. The server now uses those actual capacities. Histories with at most 128 eligible rows keep every observation. Denser histories select shared actual PM2.5, temperature and heat-index extrema and endpoints, then distribute spare sample slots through time. If byte pressure requires further reduction, selection starts from the original source observations. Full-window PM summaries and source collection gaps remain unchanged. A constrained budget below eight graph points prioritizes PM2.5; it can omit other-field extrema. The window remains six hours.

**228 portable tests passed**, including actual embedded web-JavaScript parity, exact ties, malformed/fractional clocks, stale observation labels, numeric/first-crossing independence, source-only graph rows, dense multi-channel peaks and constrained payload budgets. A synthetic 122-row response retains every row within the firmware body limit. I also restarted and checked the private live server's endpoints and labels; operational payloads remain excluded. Device parsing, display, speech, flashing and board verification belong to the firmware contribution and are not claimed by these server tests.

The [October 9 source manifest](research/2026-10-09-server-source-release.json) lists the 85 application/helper files and their hashes. The [model card](MODEL_CARD.md) retains the forecast accuracy limits. This update repairs presentation and history fidelity; it does not establish better sudden-change prediction skill.
